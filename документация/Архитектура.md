# Архитектура и данные

## Серверная архитектура

Серверный режим реализован отдельным Frappe-приложением `erp_basic` над стандартными
документами ERPNext. Решение, версии, транзакции, Site/Company и учётная политика
описаны в [ADR](../docs/adr/0001-server-foundation.md). Упрощённый `/erp` использует
серверные API; его недоступность не включает локальную базу. Отдельный Frappe Site
и БД изолируют независимого клиента; Company внутри Site — юридические лица с
согласованными общими справочниками.

Смотрите [документы и права](../docs/documents-and-access.md),
[интеграцию](../docs/clientora-integration.md), [миграцию](../docs/migration.md)
и [инструкцию окружения](../infra/README.md). Далее описана сохранённая браузерная
демонстрация, которая публикуется на GitHub Pages.

## Реализация демонстрации

| Часть | Реализация |
|---|---|
| Страница | Статический HTML |
| Интерфейс и документы | JavaScript без внешних библиотек |
| Оформление | CSS, переменные темы, адаптивная компоновка |
| Переходы | Маршруты после символа `#` |
| Хранилище | Локальное хранилище браузера |
| Обмен файлами | CSV и резервная копия JSON |
| Проверки | Встроенный механизм тестов Node.js |

## Состав модели

Демонстрационная база содержит организацию, профиль, номенклатуру, клиентов, поставщиков, предложения, заказы, реализации, оплаты, заказы поставщикам, поступления, складские документы, расходы, избранное и настройки представлений.

Основной ключ локального хранилища — `erpbasic-v2`, версия схемы — `2`. Тема хранится отдельно в `erpbasic-theme`. Сохранена однократная миграция из ранних ключей демонстрации.

## Поведение документов

Заказ определяет договорённость и сумму. Оплаты учитываются отдельно и влияют на долг. Поступления и реализации изменяют локальные остатки при подтверждении. Проверки предотвращают повторное применение одного документа и учитывают повторяющиеся позиции при контроле доступного количества.

Это модель поведения интерфейса. Она не заменяет серверные транзакции, блокировки, журналы проводок и регистры ERPNext.

## Политика безопасности страницы

Скрипты и стили вынесены в отдельные файлы. Встраиваемый вариант совместим с политикой Clientora `script-src 'self'; style-src 'self'`. Для индикатора выполнения используется стандартный элемент `progress`; фиксированные стили перенесены в классы.

Раздел демонстрации не выполняет запросов к учётным API. Сохранение документов и обмен
файлов выполняются в браузере. Серверная версия имеет отдельные вход, сессии, права и API.

## Связка с ERPNext

Clientora управляет CRM-сценариями; ERP хранит учётные документы и результаты проведения.
Серверный Basic уже использует ERPNext. Для старого JSON v2 подготовлен контролируемый
перенос начальных остатков и архива истории. Включение дополнительных модулей полного
ERPNext не требует пересоздания native документов, но новые модули, роли и рабочие данные
нужно испытать перед вводом. Точные границы проверки приведены в [отчёте](../docs/verification.md).
