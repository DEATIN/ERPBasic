# План развития

Отметки описывают код и проведённые испытания. Они не означают, что сервер уже размещён
для пользователей или что проверены все модули ERPNext. Подробные свидетельства находятся
в [отчёте о проверках](../docs/verification.md).

## Браузерная демонстрация

- [x] Русский интерфейс, две темы, списки, документы и рабочие пространства.
- [x] Локальные продажи, закупки, склад, оплаты, расходы, CSV и резервные копии JSON.
- [x] Существующие семь проверок модели и отдельная публикация GitHub Pages.

## Серверная основа

- [x] Отдельное Frappe-приложение без форка; ADR и карта стандартных документов ERPNext.
- [x] Закреплённые версии, реальные MariaDB/Redis, HTTP, worker, scheduler и обновление схемы.
- [x] Frappe login, завершение сессий, блокировка, приглашение и отдельные интеграционные пользователи.
- [x] Company User Permission, роли, проверки API, списков, стандартного REST и приватных вложений.
- [x] Серверный `/erp`: списки с пагинацией, формы, сохранение, проведение, отмена, связи и возвраты.
- [x] Устойчивые ключи команд, проверка версии и конкуренция на реальной MariaDB READ-COMMITTED.
- [x] Native продажи/закупки, физические движения, счета и распределение оплат без двойного списания.
- [x] Moving Average, запрет отрицательного остатка, переносы, списание, инвентаризация и конверсия UOM.
- [x] Неизменяемый бизнес-аудит и раздельный журнал обмена.
- [x] Зашифрованная полная копия и восстановление в новый Site/БД с проверкой файлов и ключей.
- [ ] Рабочее размещение: HTTPS, операционный мониторинг, удалённые копии, расписание и оповещения.
- [ ] Испытания на согласованном рабочем объёме, отказоустойчивость и подтверждённые RPO/RTO.

## Связанная работа с Clientora

- [x] Матрица источников справочников, документов и значимых полей.
- [x] Версионированный контракт, устойчивые ID, атомарные outbox/inbox, lease, retry и журнал.
- [x] Реальный заказ Clientora → native черновик Sales Order → проведение ERP → состояние в Clientora.
- [x] Проверки дублей, другого тела с тем же UUID, устаревших событий и потери ответа после commit.
- [x] Источник цены — ERP; CRM-статус оплаты не создаёт финансовый факт.
- [x] Контрольный импорт JSON v2: dry run, карта ID, архив исходной истории, opening stock и сверка.
- [x] Отдельный проверенный финансовый opening snapshot; демо-оплаты не выданы за банковские данные.
- [ ] Подключение конкретных рабочих организаций, цен, клиентов и номенклатуры после сверки mapping.
- [ ] Банковские/кассовые источники подтверждения оплаты и новые направления обмена по отдельным контрактам.

## Расширение до полного ERPNext

- [x] Basic использует те же стандартные документы и регистры; второй учётной модели нет.
- [x] Автоматизированная проверка сохранения native ID и SLE при открытии полного режима.
- [x] Откат описан как восстановление согласованной версии кода, данных, файлов и конфигурации.
- [ ] Полная репетиция конкретного внедрения: новые модули, роли, объём, восстановление на другом узле.
- [ ] Производство, проекты, партии/серийные номера и массовая ретроспективная переоценка.
- [ ] Регламентированный российский учёт и налоговая локализация.

Отдельная команда физического резервирования склада пока не добавлена в упрощённый UI.
Показатели резерва берутся из штатного ERPNext. Дополнительные модули и изменения учётной
политики включаются по подтверждённым сценариям, с повторной проверкой прав и движений.
